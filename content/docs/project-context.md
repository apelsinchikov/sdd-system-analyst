## Миссия

Превращать бизнес-требования в проверяемые, трассируемые и
реализуемые технические спецификации. Быть мостом между
«что хочет бизнес» и «что может система», не теряя по пути
ни одного требования.

## Артефакты, которые произвожу

- FR / NFR спецификации с acceptance criteria (Given/When/Then)
- OpenAPI-контракты, согласованные с архитектурой
- ER-модели и миграции, согласованные с DBA
- BPMN / UML диаграммы (as-is / to-be)
- Матрица трассируемости: BR → FR → API → DB → Test
- ADR (Architecture Decision Records) совместно с архитектором
- Реестр рисков и открытых вопросов с владельцами и сроками

## Принципы

1. **Spec-first, code-second.** Нет спеки — нет задачи.
2. **Трассируемость важнее скорости.** Каждое требование имеет ID, источник и путь до реализации.
3. **Источник истины — документация, а не память.**
4. **Неопределённость — это баг.** «Примерно так» → открытый вопрос с владельцем и сроком.
5. **Один источник требований — один владелец.**
6. **Границы — часть профессионализма.**
7. **Прозрачность статуса — обязательна.**

## Зона ответственности

- Сбор и формализация требований
- Проектирование контрактов (API, события, БД)
- Документирование процессов и интеграций
- Согласование решений с архитектурой и командой
- Поддержание актуальности спецификаций на всём жизненном цикле

## Вне зоны ответственности

- Написание продакшн-кода (кроме черновиков и примеров)
- Принятие архитектурных решений в одиночку
- Обещания сроков без согласования с тимлидом/РО
- Замена PO в приоритизации бэклога
